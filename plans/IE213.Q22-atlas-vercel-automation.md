# IE213.Q22 - Atlas + Vercel Automation

## Security First

The Atlas private key was pasted in chat. Treat it as exposed and rotate it in MongoDB Atlas after this setup. Do not commit `.env.deploy.local` or any generated dump archives.

## What This Automates

- Create/find MongoDB Atlas project.
- Create/find M0 Atlas cluster.
- Create/update app database user.
- Add Atlas network access for Vercel/serverless.
- Generate Atlas `MONGODB_URI`.
- Dump local MongoDB and restore to Atlas.
- Apply schema/index script to Atlas.
- Push Vercel environment variables.
- Deploy to Vercel.
- Smoke test deployed URL.

## Required Local Tools

Currently missing on this machine:

- `mongodump`
- `mongorestore`
- `vercel`

Atlas CLI is not required because Atlas automation uses the Atlas Admin API with `curl.exe` digest auth.

Install requirements:

```powershell
npm i -g vercel
```

Install MongoDB Database Tools from MongoDB official downloads and ensure these commands are on PATH:

```powershell
mongodump --version
mongorestore --version
```

`mongosh` is run through `npx -y mongosh@latest`, so global install is optional.

## Setup Env

Copy env template:

```powershell
Copy-Item .env.deploy.example .env.deploy.local
```

Fill `.env.deploy.local` locally. Minimum required:

```env
ATLAS_PUBLIC_KEY=...
ATLAS_PRIVATE_KEY=...
ATLAS_ORG_ID=...
ATLAS_PROJECT_NAME=intelligentroutex
ATLAS_CLUSTER_NAME=Cluster0
ATLAS_DB_NAME=intelligentroutex
ATLAS_DB_USER=intelligentroutex_app
ATLAS_DB_PASSWORD=<new strong password>
ATLAS_ALLOW_IP=0.0.0.0/0

LOCAL_MONGODB_URI=mongodb://miniver:miniver_dev_password@localhost:27017/intelligentroutex?authSource=admin

VERCEL_TOKEN=...
VERCEL_PROJECT_NAME=3d-web
VERCEL_PROD_DOMAIN=<your-domain-or-empty>

AUTH_SECRET=<32+ chars>
NEXTAUTH_SECRET=<32+ chars>
ADMIN_SECRET_KEY=<strong secret>
ADMIN_STEALTH_TOKEN=<strong token>
TOKEN_ENCRYPTION_KEY=<64 hex chars if token encryption is used>
```

If you do not know `ATLAS_ORG_ID`, get it in Atlas UI under Organization Settings.

## Step-by-Step Automation

### 1. Create Atlas Project/Cluster/User/Access

```powershell
powershell -ExecutionPolicy Bypass -File scripts/deploy/atlas-init.ps1 `
  -CreateProject `
  -CreateCluster `
  -CreateDbUser `
  -AllowNetwork `
  -PrintUri
```

If the project/cluster already exists, the script reuses it.

### 2. Migrate Local MongoDB to Atlas

```powershell
powershell -ExecutionPolicy Bypass -File scripts/deploy/atlas-migrate.ps1
```

This runs:

- `mongodump` from `LOCAL_MONGODB_URI`
- `mongorestore --drop` to Atlas
- `scripts/mongodb/create-current-schema.js` against Atlas

### 3. Set Vercel Env

```powershell
powershell -ExecutionPolicy Bypass -File scripts/deploy/vercel-env.ps1
```

### 4. Deploy Preview

```powershell
powershell -ExecutionPolicy Bypass -File scripts/deploy/vercel-deploy.ps1
```

### 5. Smoke Test

```powershell
powershell -ExecutionPolicy Bypass -File scripts/deploy/smoke-test.ps1 -BaseUrl https://your-preview-url.vercel.app -TestRegister
```

### 6. Deploy Production

```powershell
powershell -ExecutionPolicy Bypass -File scripts/deploy/vercel-deploy.ps1 -Prod
```
