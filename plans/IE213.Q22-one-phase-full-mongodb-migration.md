# IE213.Q22 - One-Phase Full MongoDB Migration Plan

## Objective

Migrate all remaining Supabase/Postgres runtime dependencies to MongoDB in one controlled phase before Vercel deployment.

Target result:

- Vercel build passes without Supabase env vars.
- Core runtime paths use MongoDB only.
- No route creates Supabase clients or calls `.from(...)` for application data.
- Supabase packages/config can remain temporarily only if unused, but no production route depends on them.
- `npm test`, `npm run build`, and smoke checks pass.

## Current Baseline

Already migrated:

- MongoDB local Docker and schema scripts.
- MongoDB client and typed collection helpers.
- Public products/categories/featured cache.
- Health check.
- NextAuth credentials/Google/JWT profile lookup.
- Register/verify/reset password repository path.
- Profile get/update path.
- Brute-force login tracking.
- Payment config helper.
- Auth cleanup cron.
- Vercel-like build without `.env.local` passes.

Remaining legacy inventory from `rg`:

- Around 650 text matches related to Supabase/Postgres patterns.
- High-priority route groups still include addresses, cart, checkout, orders, admin, files/uploads, notifications, wishlist, QR/payment webhook, Google Drive token persistence.
- Legacy support files still include `src/lib/supabase/*`, `src/lib/db-direct.ts`, Prisma schema, and some Supabase package dependencies.

## One-Phase Strategy

This is one phase, but split into ordered workstreams. Do not deploy mid-phase except preview smoke environments.

Rule: each workstream must preserve build/test green before moving to the next.

## Execution Rules For The One Phase

- Do not mix data model redesign with route migration unless required.
- Preserve API response shapes exactly unless UI is updated in the same commit.
- Use MongoDB references as strings to match existing UUID usage.
- Keep `_id` string and expose `id` in API responses.
- Add indexes before adding routes that depend on them.
- Any route migrated must include ownership/role checks equivalent to the old route.
- Do not delete Supabase packages until all imports are gone and build/test pass.
- Do not run destructive DB cleanup scripts against production MongoDB during migration.

## Risk Register

| Risk | Impact | Mitigation |
| --- | --- | --- |
| Multiple order models exist | Wrong order status/payment updates | Keep collections separate and add read-model mapper |
| Missing cart schema in SQL | Checkout breakage | Use Mongo-native `carts.items[]` design and test guest/user merge |
| Supabase placeholders mask runtime legacy routes | Feature fails after deploy | Workstream 9 must remove active Supabase imports before final production |
| Vercel cannot reach local MongoDB | Health/order/auth fail | Use external MongoDB URI reachable from Vercel |
| File authorization regressions | Data leak | Migrate file-access checks with explicit owner/order link tests |
| Payment webhook idempotency bug | Duplicate payments/orders | Enforce unique `idempotency_key` and transaction/reference indexes |
| Admin role check drift | Privilege escalation | Centralize admin role lookup via MongoDB/JWT |

The one-phase migration is complete only when all are true:
