# IE213.Q22 - Chuyển Schema Supabase/PostgreSQL Sang MongoDB

## Mục tiêu

Tài liệu này chuyển bộ schema SQL được cung cấp sang thiết kế MongoDB cho branch `IE213.Q22`.

Nguyên tắc chính:

- Giữ tên collection theo tên table cũ để giảm rủi ro khi migrate code.
- Giữ UUID cũ làm `_id` dạng string thay vì đổi ngay sang `ObjectId`.
- Các khóa ngoại SQL được chuyển thành field reference dạng string như `user_id`, `order_id`, `file_id`.
- Các cột `jsonb` được chuyển thành object hoặc array trong MongoDB.
- Các constraint quan trọng được thay bằng JSON Schema validator và unique/index.
- Validator đang để `validationAction: 'warn'` để không chặn dữ liệu legacy trong giai đoạn migration; khi production ổn định có thể đổi sang `error`.

## Cách chạy tạo schema MongoDB

Yêu cầu đã cài `mongosh`.

```powershell
mongosh "mongodb+srv://<user>:<password>@<cluster>/<database>" scripts/mongodb/create-schema.js
```

Không chạy script này vào production nếu chưa backup và chưa review URI.

## Kiểu dữ liệu chuyển đổi

| PostgreSQL | MongoDB |
| --- | --- |
| `uuid` | string UUID trong `_id` hoặc field reference |
| `text`, `varchar` | string |
| `timestamp with time zone` | Date |
| `jsonb` object | object |
| `jsonb` array | array |
| `numeric` | Decimal128 hoặc double |
| `integer`, `smallint`, `bigint` | int/long |
| `boolean` | bool |
| enum/user-defined type | string enum trong validator |
| foreign key | reference id string + application-level validation |

## Quan hệ nên giữ dạng reference

Nên giữ collection riêng vì các luồng admin/list/search cần query độc lập:

- `orders` và `order_items`.
- `files`, `file_links`, `order_files`, `order_item_files`, `revision_files`.
- `payments` và `payment_events`.
- `design_versions` và `design_images`.
- `products` và `product_variants`.

Có thể embed sau này nếu muốn tối ưu đọc:

- `order_addresses` có thể embed vào `orders.shipping_address_snapshot`.
- `user_profiles` có thể embed vào `users.profile`.
- `user_addresses` có thể giữ riêng nếu người dùng có nhiều địa chỉ.

## Lưu ý khi migrate dữ liệu thật

Thứ tự export/import đề xuất:

1. `users`
2. Auth tables: `accounts`, `sessions`, `verification_tokens`, `password_reset_tokens`
3. User data: `user_profiles`, `user_addresses`
4. Catalog: `categories`, `products`, `product_variants`
5. Orders: `orders`, `order_addresses`, `order_items`
6. Files: `files`, `file_links`, `order_files`, `order_item_files`
7. Design/revision: `order_revisions`, `revision_files`, `design_versions`, `design_images`
8. Payments: `payments`, `payment_events`, `payment_configs`
9. Logs/settings: `notifications`, `print_jobs`, `activity_logs`, `admin_audit_log`, `system_settings`, `order_status_history`, `order_notes`

Checklist migrate:

- Backup Supabase/Postgres trước khi export.
- Export từng table sang JSON với UUID dạng string.
- Convert timestamp sang ISODate/Date.
- Convert numeric sang number hoặc Decimal128 theo chính sách tiền tệ.
- Import vào DB staging trước.
- So sánh count từng table/collection.
- So sánh sample order end-to-end gồm user, items, files, payment, notifications.
- Chỉ chạy production sau khi staging pass.

## Việc code cần làm tiếp

- Thêm MongoDB client singleton.
- Thay `getAdminSupabase()` trong repository/service bằng MongoDB repository.
- Cập nhật auth adapter nếu không còn dùng Supabase adapter.
- Thêm integration tests với `MONGODB_TEST_URI`.
- Chạy `npm test`, `npx tsc --noEmit`, `npm run build` trước preview deploy.
