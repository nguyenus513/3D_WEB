# IE213.Q22 - MongoDB Migration Status

## Phase Result

- Branch `IE213.Q22` is migrated to MongoDB-first for deploy readiness.
- Local/self-hosted MongoDB is used; Atlas is not required.
- Supabase/Postgres env vars are no longer required for `npm test` or `npm run build`.
- Legacy Supabase helper entrypoints now route through a MongoDB compatibility adapter so old API routes use MongoDB collections instead of a live Supabase client.
- Client bundles no longer import the MongoDB driver through VietQR; public VietQR constants live in `src/lib/vietqr-public.ts`.

## MongoDB Foundation

- Local MongoDB runs through `docker-compose.mongodb.yml`.
- Current SQL schema is mapped to MongoDB in `scripts/mongodb/create-current-schema.js`.
- Local database `intelligentroutex` has the current collections and indexes applied.
- MongoDB driver is installed through `mongodb`.
- App has a MongoDB singleton client in `src/lib/mongodb/client.ts`.
- App has typed MongoDB collection helpers in `src/lib/mongodb/collections.ts`.
- App has core document interfaces in `src/lib/mongodb/documents.ts`.
- Supabase-compat bridge is in `src/lib/mongodb/supabase-compat.ts`.

## Migrated Areas

- Auth/session/profile core uses MongoDB `profiles` and token collections.
- Cached public catalog reads products/categories from MongoDB.
- Payment config service reads MongoDB `payment_configs`.
- Brute-force/security login tracking uses MongoDB `failed_login_attempts`.
- Controllers/repositories for products, orders, cart, checkout, addresses now receive MongoDB compat clients where legacy APIs remain.
- Admin/settings/stats/customer/order routes compile against MongoDB compat.
- Upload/file metadata legacy calls are routed through MongoDB compat.

## Vercel Note

Vercel cannot reach the local Docker MongoDB. Production deploy must set `MONGODB_URI` to a reachable non-Atlas MongoDB endpoint, for example a VPS/self-hosted MongoDB, Railway, Render private service, or another managed MongoDB provider.
