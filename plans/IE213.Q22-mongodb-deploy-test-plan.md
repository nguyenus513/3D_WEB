# IE213.Q22 - Kế Hoạch Kiểm Thử Deploy MERN/MongoDB

## 1. Mục tiêu

Branch `IE213.Q22` dùng để chuẩn bị phiên bản deploy với MongoDB, không làm ảnh hưởng trực tiếp branch `main`.

Mục tiêu kiểm thử:

- Xác nhận ứng dụng Next.js/React/Node API routes build và chạy ổn định trước deploy.
- Xác nhận dữ liệu nghiệp vụ hoạt động với MongoDB thay cho Supabase/PostgreSQL.
- Xác nhận các luồng chính của web e-commerce/print-on-demand hoạt động trên môi trường preview/staging.
- Chuẩn bị checklist deploy lên Vercel và phương án chạy trên Render nếu cần.
- Đảm bảo có tiêu chí pass/fail rõ ràng trước khi merge hoặc deploy production.

## 2. Phạm vi kiểm thử

### Trong phạm vi

- Auth: đăng ký, đăng nhập, reset password, session, refresh token, admin, 2FA.
- Product/catalog: danh mục, danh sách sản phẩm, chi tiết sản phẩm, featured products.
- Cart/checkout/order: giỏ hàng, merge cart, tạo đơn, trạng thái đơn, lịch sử đơn.
- Admin: quản lý sản phẩm, khách hàng, đơn hàng, dashboard, settings.
- Upload/file: presign upload, complete upload, metadata file, ràng buộc MIME/size.
- Payment/webhook: tạo payment, webhook confirmation, secret validation.
- Notification/profile/address/wishlist nếu đang còn được dùng trong UI.
- Build, lint, typecheck, unit, integration, E2E, security smoke, deploy smoke.

### Ngoài phạm vi giai đoạn đầu

- Migration dữ liệu production thật từ Supabase/Postgres sang MongoDB.
- Viết lại toàn bộ UI hoặc đổi API contract nếu không bắt buộc.
- Tự host MongoDB production trên Render.
- Kiểm thử chuyên sâu animation/3D rendering ngoài việc đảm bảo page không crash và CTA hoạt động.

Nếu cần migration dữ liệu thật, tạo plan riêng gồm mapping schema, dry-run, checksum, backup và rollback.

## 4. Môi trường và biến môi trường

### MongoDB

- `MONGODB_URI`: connection string MongoDB Atlas.
- `MONGODB_DB_NAME`: tên DB theo môi trường.
- `MONGODB_TEST_URI`: connection string cho integration test.

DB đề xuất:

- `miniver_dev`
- `miniver_test`
- `miniver_staging`
- `miniver_prod`

Không dùng chung DB test/staging/production.

### Auth/app

- `AUTH_SECRET`
- `NEXTAUTH_SECRET`
- `AUTH_URL`
- `NEXTAUTH_URL`
- `NEXT_PUBLIC_APP_URL`
- `TOKEN_ENCRYPTION_KEY`
- `ADMIN_SECRET_KEY`
- `ADMIN_STEALTH_TOKEN`

### External services

- Redis/rate limit: `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN`.
- Storage R2/S3: `CLOUDFLARE_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_BUCKET_NAME`.
- Payment/webhook: `WEBHOOK_SECRET`, `QR_WEBHOOK_SECRET` và secret payment provider đang dùng.
- Email: `GMAIL_USER`, `GMAIL_APP_PASSWORD`, `BREVO_API_KEY`.
- Google Drive/OAuth nếu còn dùng: `GOOGLE_*`.

## 5. Thiết kế kiểm thử MongoDB

### Collections cần có test

- `users`
- `profiles`
- `addresses`
- `products`
- `categories`
- `carts`
- `orders`
- `notifications`
- `refresh_tokens`
- `admin_2fa`
- `audit_logs`
- `settings`

### Indexes bắt buộc cần xác nhận

- `users.email` unique.
- `products.slug` hoặc public product id unique.
- `orders.userId`.
- `orders.status`.
- `orders.createdAt`.
- `carts.userId`.
- `carts.sessionId`.
- `refresh_tokens.tokenHash`.
- `refresh_tokens.familyId`.
- `notifications.userId` và `notifications.read`.

### Rủi ro MongoDB cần test kỹ

- NoSQL injection với payload chứa `$ne`, `$gt`, `$where`, object thay vì string.
- ObjectId/string id không hợp lệ.
- Duplicate key khi register hoặc tạo product slug trùng.
- Query thiếu index ở admin order/product list.
- Connection leak trên serverless nếu không dùng singleton client.
- Sai DB do env staging/production bị trỏ nhầm.

## 7. Integration test với MongoDB

Chạy trên DB test hoặc MongoDB memory server.

Các case bắt buộc:

### User/auth

- Register user mới thành công.
- Register email trùng bị reject.
- Login đúng credentials thành công.
- Login sai credentials bị reject.
- Refresh token rotate thành công.
- Reuse refresh token cũ bị revoke/reject.
- Reset password đổi được password và invalidate token cũ.

### Product/category

- Tạo category.
- Tạo product có category hợp lệ.
- Product slug/id trùng bị reject.
- List products có pagination/sort/filter.
- Update product không làm mất fields không gửi lên.
- Ẩn/xóa mềm product không còn hiện ở public list.

### Cart/checkout/order

- Guest add item vào cart.
- User login merge guest cart vào user cart.
- Update quantity đúng total.
- Remove item đúng total.
- Checkout tạo order từ cart.
- Order items snapshot đúng price/product tại thời điểm đặt.
- Không checkout được cart rỗng.
- Không checkout được product inactive/out-of-stock nếu có rule này.

### Admin/order

- Admin xem danh sách orders.
- User thường không gọi được admin API.
- Update order status theo đúng state machine.
- Không cho chuyển trạng thái sai luật.
- Audit log ghi nhận action quan trọng.

### Upload

- Presign upload trả metadata hợp lệ.
- Complete upload lưu file metadata vào MongoDB.
- File thuộc đúng user/order.
- Reject file sai MIME, quá size, hoặc path không hợp lệ.

Tiêu chí pass:

- Test cleanup dữ liệu theo test run id.
- Không xóa nhầm DB staging/production.
- Integration test pass trên local và CI branch `IE213.Q22`.

## 10. Security test

Chạy:

```bash
npm audit --audit-level=high
```

Checklist:

- Không commit `.env.local` hoặc secrets.
- Không log `MONGODB_URI`, token, webhook secret, service key.
- Cookie production có `httpOnly`, `secure`, `sameSite` phù hợp.
- CSRF/rate limit hoạt động với endpoint write quan trọng.
- User không truy cập được admin endpoints.
- User không xem/sửa dữ liệu của user khác.
- Webhook reject nếu thiếu/sai secret.
- File upload reject path traversal và executable.
- NoSQL injection payload bị reject/sanitize.
- Security headers có CSP, HSTS, X-Frame-Options, X-Content-Type-Options, Referrer-Policy.

## 11. Performance và stability

Kiểm thử:

- `npm run build` không lỗi memory/time.
- API `/api/health` phản hồi nhanh.
- Product list pagination không query full collection.
- Admin order list có index và pagination.
- MongoDB connection được reuse giữa requests.
- Cold start trên Vercel không làm timeout các route chính.
- External service lỗi tạm thời không làm crash toàn app.

Ngưỡng đề xuất cho staging:

- Health check dưới 1 giây.
- Product list dưới 2 giây với dữ liệu seed trung bình.
- Admin order list dưới 3 giây với pagination.
- Không có MongoDB collection scan lớn ở luồng chính.
